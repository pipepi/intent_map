# Intent Map：方案与产品定位

[← 返回项目 README](../README.md)

## 一句话定位

Intent Map 是一个业务无关的分形节点地图编辑器，以 `.pip` 应用的形式运行，用于构建、观察、编辑、组合和导出其他节点应用。

软件开发复杂度掌控是运行在 Intent Map 上的一组可选业务节点能力；Crypto 交易所是验证这组能力的实际应用案例；人、Agent、脚本和其他工具都是可选的操作者。

## 总体结构

```text
不可变基础
└── Seed：无状态的原生初始加载器
        ↓ 加载
可演进加载能力
└── loader.pip：新版加载器
        ↓ 加载
通用节点应用
└── intent-map.pip：分形节点地图编辑器
        ↓ 编辑和运行
通用业务能力
└── software-authoring.pip：软件开发复杂度掌控
        ↓ 应用于
实际案例
└── crypto-exchange.pip：Crypto 交易所

可选操作者
├── 人
├── Agent（可通过 MCP）
├── 脚本与常规程序
└── 外部工具和团队成员
```

这几层彼此解耦：Intent Map 不认识软件开发或交易所，软件开发能力不依赖 Agent，Agent 也不是 `.pip` 成立和运行的前提。

## Seed：唯一原生且稳定的种皮

Seed 是系统中唯一需要操作系统直接双击运行的原生文件。它应当无状态、尽可能小，并长期保持稳定。

Seed 的核心职责只有：

```text
读取 .pip
→ 验证包结构
→ 提供最小运行环境
→ 启动 .pip 入口
```

Seed 不包含具体业务，不承担 Intent Map 的编辑能力，也不吸收持续变化的加载器功能。它类似最小 bootloader：负责让系统开始运行，而不是成为整个系统本身。

## `loader.pip`：可演进的加载器

新版加载器本身也是 `.pip`，由 Seed 加载。需要持续演进的能力可以放在加载器中，例如：

- 文件选择和最近打开记录；
- PIP 包管理与版本兼容；
- 更新、恢复和错误呈现；
- 权限确认；
- 本地或远端 PIP 获取；
- 不同运行入口的选择。

这样，加载体验可以像普通应用一样升级，而不需要频繁更换原生种皮。

## `intent-map.pip`：业务无关的节点编辑器

Intent Map 本身也是一个普通 `.pip`，不享有特殊宿主地位。它提供通用的节点地图能力：

- 创建、编辑、删除和移动节点；
- 分形嵌套、缩放与作用域聚焦；
- 输入输出端口和连接；
- 节点组合、引用和投影；
- 选择、历史、导入和导出；
- 观察与运行节点应用；
- 编辑包括自身在内的 `.pip`。

Intent Map 的内核不应内置“聊天、业务内树、UI、数据库、API、代码、交易所或 Agent”等领域概念。这些都应由具体业务节点和 PIP 应用提供。

因此，Intent Map 的准确定位是：

> 一个业务无关、可自举的分形节点地图编辑器。

## `.pip`：统一的可运行、可编辑和可分发单元

`.pip` 不是只用于 Intent Map 的文件格式，也不只是压缩包或最终可执行文件。它是系统统一的应用和协作单元，可以同时承载：

- 节点及其结构；
- 应用逻辑和运行入口；
- 代码、资源、配置及其他原生产物；
- 编辑所需的结构化信息；
- 与其他 PIP 的组合或引用；
- 人或工具继续操作所需的上下文。

它更接近 `.blend` 或 `.psd`：既包含可呈现或可运行的结果，也保留继续创作所需的结构。

系统具有递归和自举关系：

```text
Seed 运行 .pip
.pip 可以是加载器
加载器打开 .pip
.pip 可以是 Intent Map
Intent Map 编辑 .pip
.pip 又可以生成、组合或分发新的 .pip
```

一句话概括：

> Seed 负责启动，`.pip` 负责一切演进。

## `software-authoring.pip`：软件开发复杂度掌控能力

“掌控软件开发复杂度”不是 Intent Map 的内置定位，而是由一组业务节点组合出来的应用能力。它可以被实现和分发为 `software-authoring.pip`，并由 Intent Map 打开、编辑和运行。

它的核心策略是：

> 在合适颗粒度的树枝上达成共识，建立掌控边界；每次只聚焦并填充一个人能够理解、修改、接管或推倒重来的小范围。

整个软件像由许多方格组成的分形轮廓。树枝决定方格颗粒度：方格太大时继续展开，足够清楚时停止分解并开始填充。

```text
观察整体轮廓
→ 选择一根树枝
→ 聚焦到合适颗粒度
→ 达成局部共识
→ 手工、协作或借助工具填充
→ 回到整体观察
→ 不满意则局部修改或推倒重来
```

这里的掌控不等于避免错误或证明业务判断正确。用户可能有意选择非常规、不完整甚至表面矛盾的方案，以服务更深层目标。掌控意味着始终具备：

- **可理解**：当前局部在人可理解的范围内；
- **可修改**：产物可以直接手工编辑；
- **可接管**：可以在人工、协作和自动化之间切换；
- **可重来**：局部失败不必推翻整体；
- **可聚焦**：只披露当前所需的复杂度；
- **可组合**：完成的局部可以重新折叠进整体。

## 软件开发应用中的内树

“内树”是 `software-authoring.pip` 提供的业务概念，不是 Intent Map 内核的固定结构。

在这一应用中，第一层聊天用于探索、提问和协商，第二层内树用于沉淀实现无关的业务共识：

- 业务核心物流动场景；
- 参与者、输入和输出；
- 前置条件和结果；
- 正常流动与异常分支；
- 业务约束和人工决策点；
- 已经形成共识的局部边界。

内树不需要出现 React 组件、HTTP 路由、数据库表、编程语言或部署平台。即使不存在任何外树或代码实现，它也依然可以独立用于业务梳理、协作和知识传递。

内树也不裁判业务是否“正确”。系统可以呈现矛盾、风险和可能后果，但由用户决定保留、修改、暂缓或继续探索。

## 软件开发应用中的可选外树

UI、DB Tables、API、代码等是从内树某个范围、以特定视角派生的可选外树，而不是内树的组成部分，也不是强制流水线。

```text
内树
├── 0..N 个 UI 投影
├── 0..N 个 DB Tables 投影
├── 0..N 个 API 投影
├── 0..N 个代码投影
└── 0..N 个其他领域投影
```

外树可以完全不存在，也可以只覆盖一根局部树枝。同一树枝可以拥有多个候选投影；外树可以删除、替换或重新生成，而不损害内树。

系统采用乐观创作方式，不要求所有外树永久自动一致。发现不满意或不一致时，用户只需选择：

- 局部推倒重来；
- 直接手工修正；
- 保留现状继续探索；
- 回到对应树枝重新讨论。

## 八层渐进式披露

`software-authoring.pip` 可以提供八层软件创作视角，但这些层是可选的披露方向，而不是必须顺序完成的流程。

| 层级 | 含义 | 典型内容 |
|---|---|---|
| 第一层：聊天 | 探索空间 | 意图表达、追问、协商、候选方案 |
| 第二层：内树 | 掌控核心 | 业务核心物流动场景与约束 |
| 第三层：交互与契约 | 可选外树 | UI、DB Tables、API |
| 第四层：后端代码 | 可选实现 | 业务逻辑、数据访问、API 实现、测试 |
| 第五层：前端代码 | 可选实现 | 页面、组件、状态、交互、API 集成 |
| 第六层：外围系统 | 现实环境 | 身份、支付、消息、第三方服务、基础设施 |
| 第七层：分发 | 抵达用户 | 构建、部署、渠道、安装、升级和交付 |
| 第八层：分利润 | 价值闭环 | 收费、成本、结算、分成与激励 |

用户始终立足第二层，可以向任意相关层逐步披露，也可以跳过、停止或使用已有产物。每个局部均可以：

- 完全手工实现；
- 由团队成员协作实现；
- 使用脚本、模板或普通工具生成；
- 人先写、Agent 补全；
- Agent 先写、人修改和接管；
- 完全委托 Agent；
- 挂接外部已有实现。

Agent 在这里是可选的效率工具，不是方法成立的前提。

## `crypto-exchange.pip`：实际应用案例

软件开发复杂度掌控能力本身仍然需要真实案例验证。Crypto 交易所适合作为首个案例，因为它包含大量相互关联但可以分形拆解的领域：

- 用户、身份与合规；
- 充值、提现和钱包；
- 账户、资产与账本；
- 订单、撮合、成交与清算；
- 行情、费率和风控；
- 运营、审计与安全；
- 高并发和外围系统；
- 部署、分发、收费与分润。

一个简化的业务内树可以是：

```text
Crypto 交易所
├── 用户进入并建立身份
├── 资产进入交易所
├── 用户表达交易意图
├── 订单进入撮合
├── 成交结果完成清算
├── 用户管理资产
├── 资产离开交易所
└── 平台收费并进行价值分配
```

选择其中“冻结所需资产”树枝后，用户可以按需展开 UI、DB Tables、API、后端代码或测试，也可以只保留内树。这个案例同时验证三件事：

1. Intent Map 能否承载真实、深层和跨领域的分形节点应用；
2. 软件开发节点能力能否把大型系统拆成可掌控的局部；
3. `.pip` 能否保存、运行、编辑、组合并继续分发这些产物。

## Agent 与 PIP MCP Server：可选操作方式

没有 Agent，用户仍可以创建、分解、投影、填充、导入和导出节点。Agent 只是可选操作者之一。

当需要 Agent 参与时，PIP MCP Server 为不同 Agent 提供统一的结构化操作接口，避免每个 Agent 各自解析和改写 `.pip` 内部格式。

```text
Agent / Codex / IDE
        │ 可选 MCP
        ▼
PIP MCP Server
├── 打开和概览 .pip
├── 聚焦与读取树枝
├── 创建、更新和移动节点
├── 创建与填充投影
├── 挂载或修改局部产物
├── 导入现有项目和文件
└── 校验与导出 .pip
        │
        ▼
      .pip
```

MCP 应优先提供围绕节点和树枝的语义化动作，例如：

- `open_pip`、`get_overview`；
- `focus_branch`、`get_branch`、`list_children`；
- `create_node`、`update_node`、`move_branch`；
- `create_projection`、`replace_projection_branch`；
- `attach_artifact`、`read_artifact`、`patch_artifact`；
- `import_artifacts`、`export_pip`、`validate_pip`。

Agent 可以只读取当前树枝所需的上下文，从而减少 token 消耗和上下文漂移。Intent Map 可以接收并组织多个 Agent 的输出，也可以通过 MCP 向 Agent 提供下一轮操作入口；但这种上下游循环只是 `.pip` 的一种可选使用方式。

## 产品形态：节点应用的 Blender / Photoshop

Intent Map 在形态上更接近专业创作软件，而不是固定领域的应用生成器。

| Blender / Photoshop | Intent Map / PIP |
|---|---|
| 场景、画布 | 分形节点地图 |
| 对象、图层 | 节点、树枝和可选投影 |
| 分组与层级 | 分形嵌套与作用域 |
| 缩放、聚焦 | 选择合适颗粒度 |
| 选区 | 人或工具操作的局部边界 |
| 手工工具 | 节点编辑能力 |
| 插件与生成工具 | Agent、脚本及其他工具 |
| `.blend` / `.psd` | `.pip` |
| 渲染与导出 | 运行、组合和分发 |

Intent Map 掌控的是通用节点应用的结构复杂度。软件开发复杂度掌控只是其中一套重要业务节点能力。

## 核心价值与产品原则

Intent Map 的核心价值是提供一个通用、递归、可编辑的节点应用环境；软件开发能力包的核心价值是通过分形边界和逐层披露，提供对软件复杂度的超强掌控力。

整体原则如下：

1. **Seed 极小且稳定**：只有启动能力必须原生分发。
2. **一切演进进入 `.pip`**：加载器、编辑器、能力和案例都可独立升级。
3. **Intent Map 业务无关**：领域语义由业务节点提供。
4. **PIP 递归可组合**：应用可以加载、编辑、生成和分发其他应用。
5. **软件开发只是一个应用方向**：不硬编码进编辑器内核。
6. **内树属于软件开发能力包**：作为业务共识核心独立成立。
7. **外树全部可选**：不存在固定、强制的实现流水线。
8. **用户决定颗粒度和披露深度**：复杂度按需展开。
9. **乐观试错**：允许不一致，以手工修正或局部重来保持掌控。
10. **实现方式可替换**：人工、团队、Agent、脚本和外部工具地位平等。
11. **Agent 是可选操作者**：MCP 是可选接入层，而非系统前提。
12. **交付仍可继续编辑**：每个 `.pip` 既是结果，也是下一轮创作的输入。

## 最小验证路径

建议依次验证：

1. Seed 能稳定验证并启动一个 `.pip`；
2. Seed 能启动可演进的 `loader.pip`；
3. `loader.pip` 能打开 `intent-map.pip`；
4. Intent Map 能创建、编辑、运行和导出另一个 `.pip`；
5. `software-authoring.pip` 能提供内树、可选外树和逐层披露能力；
6. 用户可以完全手工完成一个局部填充；
7. Agent 可以通过 MCP 完成同一局部填充，且结果仍可人工接管；
8. `crypto-exchange.pip` 能以真实业务证明分形颗粒度的掌控价值；
9. 完成的 PIP 可以再次加载、修改、组合和分发。

## 最终定位

> Intent Map 是一个以 `.pip` 运行和分发的业务无关分形节点编辑器；Seed 是唯一无状态且稳定的原生初始加载器，其余加载器、编辑器、能力和应用都作为可演进的 `.pip` 存在。

> 软件开发复杂度掌控是一套运行在 Intent Map 上的可选节点能力，Crypto 交易所是其实际案例；人、Agent 和其他工具可以在合适颗粒度的树枝内自由选择如何填充。
